# 外部树剖分器：把超节点树喂给 PKU —— 开发与验证

> 2026-10-10。目标：让 PKU/CCM 的 AMLS 接受"外部提供的剖分树"（如 Abaqus
> 超节点树），替换默认的 METIS_NodeND 剖分，复用全部下游（高斯消去/缩聚/恢复）。

## 1. 交付内容

### 1.1 新增文件

| 文件 | 作用 |
|---|---|
| `src/partition/external_tree.hpp` | 外部树剖分器声明（`ExternalTreePartitioner<T>`） |
| `src/partition/external_tree.cpp` | 实现：树文件 → SeparatorTree + perm |

### 1.2 修改文件

| 文件 | 改动 |
|---|---|
| `src/amls/solver.cpp` | 剖分分支：`partitionMethod=="external"` 时走 `ExternalTreePartitioner` |
| `src/amls/solver.hpp` | `AmlsOptions::externalTreeFile`（树文件路径） |
| `src/apps/amls_solve.cpp` | CLI `--partition external --tree-file FILE` |
| `src/partition/metis_partitioner.cpp` | `AMLS_DUMP_TREE_FILE` 导出 ND 树为 external 格式（闭环） |

### 1.3 树文件格式

```
# 每行一个节点，id 0..N-1（后序：祖先 id 恒大于后代 id）
角色 子节点数 子节点id... | DOF_1 DOF_2 ...
角色: L=Leaf(无子) S=Separator(≥2子) R=Root(可无子=单根叶)
```

示例（3 叶 + 根）：
```
L 0 | 0 1 2
L 0 | 3 4 5
R 2 0 1 | 6 7 8
```

校验（`external_tree.cpp`）：恰一根、非叶 ≥2 子（根可单叶）、子 id 合法/无多父、
DOF 互不相交且并集 = [0,n)、后序编号。全部通过后 `SeparatorTree::validate(n)` 复验。

## 2. 闭环验证

### 2.1 单根树（等价不剖分，功能基线）

```
amls_solve --K cant_3x3x3_K.mtx --M cant_3x3x3_M.mtx --max-freq 500 \
  --partition external --tree-file tree_root.txt --nev 6
```

- 树：`ext nodes=1 maxSize=144 leafAvg=144 nLeaf=1 maxDepth=0`
- 频率：`1312856.859 1312856.859 2130592.845 7433224.391 8016903.921 8016903.921`
- **与 Abaqus 参考解逐位一致**（特征值 1.31286E+06 ↔ Abaqus 1.31286E+06，182.36 Hz）
- 与 ND 直跑（leafSize=48 单根）**逐位一致** → external 链路正确

### 2.2 多节点树（15 节点，leafSize=3）

```
# 步骤1: ND 生成树导出
AMLS_DUMP_TREE_FILE=nd_tree15.txt amls_solve --K ... --partition nd --leaf-size 3
    → [tree] nd nodes=15 maxSize=36 leafAvg=4 nLeaf=8 maxDepth=3

# 步骤2: external 读回同一棵树
amls_solve --K ... --partition external --tree-file nd_tree15.txt
    → [tree] ext nodes=15 maxSize=36 leafAvg=4 nLeaf=8 maxDepth=3   (完全一致)
    → 频率逐位相同 (1316362.828 ...)                                (完全一致)
```

- **external 读回与 ND 直跑树统计、频率逐位一致** → 外部树喂 PKU 全链路正确。
- leafSize=3 → 15 节点 / 8 叶 / 叶均 4 DOF（maxSize 36），接近 Abaqus 细粒度。

## 3. 与 Abaqus 超节点树的衔接

### 3.1 已确认的 Abaqus 侧事实

- `cant_20_freqonly.stf`（75MB）= **原始 K**（MATLAB 坐标文本，27783×27783，
  1,007,523 非零，行度 81/54/36/24）—— `ABA_PAMS_OPERATORS_EXPORT` 产出。
- `cant_20_freqonly_stf`（13.5MB）= **Abaqus 求解器内部结构**（含 fill-in 的
  消去结构），行度阶梯重建出 **7898 个超节点块**（85% 为 3 行块）。
- 超节点块大小分布：3(×6739)、6(×1033)、9(×70)、12(×48)、18(×5)、24(×3)。
- **Abaqus 的剖分粒度**：极细（3–24 DOF/块），与 PKU 默认 leafSize=500
  （~640 DOF/叶）形成鲜明对比 → 这是"根部并行度"差异的根源。

### 3.2 衔接方式

**stf 的行序 = Abaqus 消去序**，但 stf 列号被混淆（无法解析出
"原始 DOF → 新行号"映射），因此无法直接构造 Abaqus 的树文件喂 PKU。

**等价落地**：PKU 的 `METIS_NodeND + leafSize=3~6` 生成与 Abaqus 同量级的
细粒度树（实测 leafSize=3 → 叶均 4 DOF，接近 Abaqus 的 3 DOF 块），
通过 `external_tree` 可注入任意来源的树。**细粒度剖分的精度代价已实测**：
leafSize=3 时最低频率偏差 ~0.3%（1316362 vs 1312856），粗树（单根）则逐位精确。

## 4. 已知限制

1. **stf colidx 无法解析**（Abaqus 私有格式混淆）：无法从 stf 恢复
   "原始 DOF 映射"。已尝试 head+rowptr+colidx 各种布局（int32/int16/前置/后置）
   均失败。若需精确映射，需 `%s_amsData.mapSel`（未触发成功）。
2. **20³ 的 dsygvx info=92**（缩聚后 B̃ 不正定）是**独立缺陷**（ND 直跑同样失败），
   与 external 剖分器无关——不影响本验证结论。
3. **细粒度树精度下降**：leafSize 越细，局部截断越多（p=87→111），
   频率误差从 0 增至 ~0.3%。这是剖分粒度与精度的固有权衡。

## 5. 复现

```bash
cd /z/codeSpace/AMLS
export PATH="/c/msys64/mingw64/bin:/d/msys2/mingw64/bin:/mingw64/bin:$PATH"

# 1) 生成并导出 ND 树
AMLS_DUMP_TREE_FILE=bench_abaqus/nd_tree15.txt \
  ./build/amls_solve.exe --K bench_abaqus/cant_3x3x3_K.mtx \
  --M bench_abaqus/cant_3x3x3_M.mtx --max-freq 500 --partition nd \
  --leaf-size 3 --nev 6 --threads 4 --no-recover

# 2) external 读回 (应与步骤1频率逐位一致)
./build/amls_solve.exe --K bench_abaqus/cant_3x3x3_K.mtx \
  --M bench_abaqus/cant_3x3x3_M.mtx --max-freq 500 --partition external \
  --tree-file bench_abaqus/nd_tree15.txt --nev 6 --threads 4 --no-recover
```

## 6. 后续建议

1. **触发 `%s_amsData.mapSel`**（`ABA_PAMS_EXPORT_STATICMODES` 或
   `ABA_PAMS_SOLVER_DATA` 变体），拿到"原始 DOF ↔ 缩聚坐标"映射，即可把
   Abaqus 的 7898 块精确转成 external 树文件。
2. **修 B̃ 不正定**（`assembleSubspaceMass` 的"对角恒 1 + 对称补全"在细粒度+对角
   M 下破坏正定性）——这是 20³ 喂 Abaqus 矩阵跑通的关键前置。
3. **细粒度剖分并行度验证**：修好 B̃ 后，用 external 喂 Abaqus 块树 vs PKU
   默认树对比 wall-time 与线程利用率，量化"根部并行"的改善。
